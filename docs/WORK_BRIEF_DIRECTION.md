# ailhat Work Brief — Product Boundary

**Status:** Agreed direction — 2026-09-05

ailhat is **Portfolio Intelligence**, not a prompt-engineering generator.

Prompt generation may be a useful adapter output, but the primary job is to determine what deserves attention across a portfolio and why.

## Core transformation

**signals → interpretation → evidence → priority → work brief**

A useful ailhat work brief should be able to carry:

- signal type: Opportunity / Risk / Drift / Work
- evidence and provenance
- why this matters now
- affected product / surface / workflow
- desired outcome
- known constraints and regression boundaries
- uncertainty / missing evidence
- recommended next action
- acceptance criteria

The work brief can then combine with relevant ALVIRA Context when the execution environment needs human/product context that the portfolio signal alone does not contain.

## Ecosystem handoff

**ailhat** identifies and explains what deserves work.

**ALVIRA** supplies selected durable context and, where appropriate, a canonical Build Brief / specification of what the user actually means.

**Agent OS / Workforce** carries authorized work through tasks, workflows, harnesses, hosts, handoffs, state, and evidence. It remains infrastructure, not a standalone public product offering.

**LEDGATo** governs execution-time authority/evidence where consequential action requires enforcement, approval/resume, revocation, cost/accountability, and post-action verification.

**Human acceptance** determines whether the result is actually right and done.

## Product language

Prefer:
- work brief
- evidence-backed recommendation
- opportunity / risk / drift / work
- what deserves attention and why

Avoid as primary positioning:
- prompt engineer
- prompt generator
- autonomous task bot

The prompt is an adapter. The intelligence is the product.
